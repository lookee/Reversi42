🎯 Board Representation Formats

Confronto tra diverse modalità di rappresentare la scacchiera in JSON

Format 1: Stringa 64 caratteri BAD READABILITY BEST SIZE
Stringa singola compatta di 64 caratteri
Pro: Minimo overhead, facilissimo da copiare/incollare
Contro: Completamente illeggibile per umani
{ "positions": [ "...........................WB......BW..........................." ] }
Format 2: Array di righe GOOD READABILITY GOOD SIZE
Ogni riga è una stringa separata, mantiene la struttura 8x8
Pro: Molto più leggibile, mantiene struttura visiva
Contro: Ancora difficile da editare manualmente
{ "positions": [ [ "........", "........", "........", "...WB...", "...BW...", "........", "........", "........" ] ] }
Format 3: Array di oggetti EXCELLENT READABILITY LARGE SIZE
Ogni cella è un oggetto con coordinate e colore
Pro: Leggibilissimo, facile da capire e modificare
Contro: Molto verbose, file grande
{ "positions": [ [ {"row": 4, "col": 4, "piece": "W"}, {"row": 4, "col": 5, "piece": "B"}, {"row": 5, "col": 4, "piece": "B"}, {"row": 5, "col": 5, "piece": "W"} ] ] }
Format 4: Matrice 2D GOOD READABILITY MEDIUM SIZE
Array di array, accesso diretto con indici
Pro: Struttura chiara, accesso diretto
Contro: Ripetitivo (include anche celle vuote)
{ "positions": [ [ [".", ".", ".", ".", ".", ".", ".", "."], [".", ".", ".", ".", ".", ".", ".", "."], [".", ".", ".", ".", ".", ".", ".", "."], [".", ".", ".", "W", "B", ".", ".", "."], [".", ".", ".", "B", "W", ".", ".", "."], [".", ".", ".", ".", ".", ".", ".", "."], [".", ".", ".", ".", ".", ".", ".", "."], [".", ".", ".", ".", ".", ".", ".", "."] ] ] }
Format 5: Solo coordinate occupate GOOD READABILITY BEST SIZE
Solo le celle con pedine, formato compatto
Pro: Minimo possibile, solo info essenziali
Contro: Richiede parsing per ricostruire la board
{ "positions": [ [ {"coord": "D4", "piece": "W"}, {"coord": "E4", "piece": "B"}, {"coord": "D5", "piece": "B"}, {"coord": "E5", "piece": "W"} ] ] }
Format 6: Human Readable EXCELLENT READABILITY GOOD SIZE
Separazione netta tra bianchi, neri e vuote
Pro: Leggibilissimo, facile da modificare
Contro: Richiede parser custom
{ "positions": [ { "black": ["D5", "E4"], "white": ["D4", "E5"] } ] }
Format 7: ASCII Art EXCELLENT READABILITY MEDIUM SIZE
Rappresentazione visuale immediata
Pro: Completamente comprensibile a colpo d'occhio
Contro: Non è JSON valido standard 
    A B C D E F G H

💡 Raccomandazioni
Per leggibilità:
Format 3 (Array of Objects) o Format 6 (Human Readable)
Per compattezza:
Format 1 (String) o Format 5 (Coordinates only)
Per equilibrio:
Format 2 (Array of Rows) - CONSIGLIATO
